# 새 환경 실행 기록 (TimoAleph 시험0 참고 구현 초안)

> 오너 시험0 계정용 참고 구현 후보의 기록 **양식 초안**입니다. 아직 아무것도 실행하지 않았으므로 모든 결과 칸은 "미확인"입니다.
> 이 기록은 학생(또는 승인된 시험0 검수) 진술입니다. AI 원문 검토나 이 기록 자체는 실행 성공의 증명이 아닙니다.

## 1. 대상

| 항목 | 값 |
|---|---|
| 제출 커밋 | 미확인(조립한 새 프로젝트의 커밋을 적음) |
| 앱 버전 | 검증 중 버전(v1.0 아님) |
| Node.js 버전 | 미확인 |
| 운영체제 | 미확인 |
| 새 폴더 | 미확인(기존 폴더와 다른 빈 폴더여야 함. 로컬 절대경로는 적지 않고 "새 빈 폴더"로만 적음) |

## 2. 절차

1. 기존 폴더는 그대로 두고 저장소를 새 빈 폴더에 내려받습니다.
2. 학생 설명서(`docs/STUDENT_GUIDE.md`)대로 Node.js를 확인하고 앱을 실행합니다.
3. 13~20단계 기능을 하나씩 눌러 결과를 적습니다.
4. 끄고 다시 켠 뒤 같은 결과인지 봅니다.

## 4. 데이터 보존

- `student/extension.mjs`는 화면 안의 걸러 보기·상세 선택만 브라우저 메모리에 두며 파일·저장소에 쓰지 않습니다.
- 학생 화면의 걸러 보기·상세 선택은 앱을 다시 실행할 때 복원되는 저장 기록으로 취급하지 않습니다. 조치 기록은 제공 서버의 `src/actions/store.mjs`가 명시적으로 전달받은 기존 SQLite 파일에 저장하며, `student/engine-adapter.mjs`는 호스트가 제공한 본인 범위 조회를 전달합니다. 프로젝트 폴더를 복사하는 것만으로 서버·엔진 기록을 백업했다고 쓰지 않습니다.
- 실행 전 보관 계획: 기존 프로젝트 폴더와 `.git`, 학생 코드·문서·기존 1~3차 기록은 그대로 유지합니다. 확인할 코드·문서의 보관 커밋과 버전을 기록하고, 새 환경 검수는 기존 폴더와 다른 새 빈 폴더에서 진행합니다. 기존 폴더에 덮어쓰거나 강제로 초기화하지 않습니다.
- 복원 계획: 문제가 생기면 기존 폴더를 수정하지 않고 보관한 커밋의 코드·문서를 또 다른 새 빈 폴더에 복원해 비교합니다. 계정 자격·키·연결 증명을 복사해 연결을 재현하지 않습니다. 서버·엔진의 실제 저장 경로, 백업 시점과 담당자의 복원 절차는 제공 구성에 따라 별도로 확인해야 합니다.
- 위 내용은 소스에서 확인한 저장 책임과 앞으로의 보관·복원 계획입니다. 백업·복원 명령, 새 환경 실행, 서버·엔진 데이터 복원은 아직 수행하지 않았으며 성공 결과로 기록하지 않습니다.

## 5. 기다림(UNV)과 미해결

- 실제 AI 연결·설명, 실제 원천 조치 집행, 실제 OSV 조회
- 같은 최종 소스로 13~20 전체와 새 환경 실행을 함께 확인하는 공식 자동 확인과 접수 연결
- 마무리 단계의 포장·새 폴더 설치·바로가기 실행 증거는 이 기록과 별개입니다. 22단계 통과 뒤 오너가 승인한 시험0 절차에서 따로 남깁니다.

v1.0 표시는 19단계 실제 실행 연결과 22단계 누적 재현·공식 접수 연결까지 완료·수용된 경우에만 합니다. 지금은 해당하지 않습니다.
